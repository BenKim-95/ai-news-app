# 뉴스 수집기 기능 개발 워크플로우

새 기능을 개발할 때 브랜치 생성부터 main 병합까지 순서대로 진행합니다.
브랜치 이름: $ARGUMENTS

## 1단계: 현재 상태 확인

1. `git status`와 `git branch --show-current`로 현재 상태를 확인한다.
2. 현재 브랜치가 `main`이 아니면 경고하고, main으로 이동할지 사용자에게 물어본다. 답을 받기 전에는 다음 단계로 넘어가지 않는다.
   - 커밋하지 않은 변경 사항이 있으면 함께 알려 준다. 변경 사항이 있는 채로 이동하면 문제가 생길 수 있으니 이동 전에 확인한다.
   - 사용자가 동의하면 `git checkout main`으로 이동한다.

## 2단계: 새 브랜치 만들기

1. `$ARGUMENTS`에 이름이 있으면 그 이름으로 `git checkout -b <이름>`을 실행한다.
2. 이름이 비어 있으면 어떤 기능을 개발할 것인지 물어본다. 답을 받으면 영어 소문자-하이픈 형식(예: `category-filter`, `notion-save`)으로 브랜치 이름을 제안하고, 사용자가 확인하면 그 이름으로 만든다.
3. 만든 뒤 "`<이름>` 브랜치가 만들어졌습니다."라고 알려 준다.
4. 이어서 "이제 개발을 시작하세요!"라고 안내한다.
5. `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 알려 준다. 기억에 의존하지 말고 파일의 현재 내용을 기준으로 요약한다.
   - 기술 스택: 프레임워크, 로그인, DB, Claude 모델, Notion 연동, RSS 라이브러리
   - 컨벤션: 계층 규칙(외부 연동은 `src/lib/`에만), 비밀 키는 서버에서만 사용, 모든 데이터는 `user_id` 기준 분리, UI는 `ui.md`, 요구사항은 `PRD.md` 우선, Next.js 16 등 버전 주의 사항
6. 마지막으로 "개발이 끝나면 '완료' 또는 'done'을 입력하세요."라고 알려 준다.

## 3단계: 커밋과 병합

사용자가 '완료' 또는 'done'을 입력하면 진행한다.

1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여준다.
2. 변경 내용을 바탕으로 커밋 메시지를 제안한다. 이 저장소의 기존 커밋처럼 한국어로, 무엇을 했는지 한 줄로 쓴다. (`git log --oneline -5`로 문체를 확인한다.)
3. 사용자가 확인하면 변경 파일을 add하고 커밋한다. `.env.local` 같은 비밀 파일이 포함되지 않았는지 먼저 확인한다.
4. `git checkout main` 후 `git merge <브랜치 이름>`으로 병합한다. 충돌이 나면 멈추고 사용자에게 알린다.

## 4단계: 작업 요약

병합이 끝나면 다음을 요약해서 보여준다.

- 브랜치 이름과 병합 결과
- 커밋 메시지
- 변경된 파일 목록과 각 파일에서 한 일
- 다음에 할 일 (예: `npm run build`와 `npm run lint` 실행, 브랜치 삭제 여부)
